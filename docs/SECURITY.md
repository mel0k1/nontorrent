# Конвейер безопасности NonTorrent

Этот документ описывает, как NonTorrent решает главную проблему торрентов —
вредоносные файлы внутри раздач, — какие решения принимает движок на каждой
ступени и какие у подхода ограничения.

## Принцип: проверять до того, как файл готов целиком

Классический сценарий: пользователь скачивает 8 ГБ раздачи, где среди
безобидных файлов лежит `crack.exe`. Обычный клиент молча отдаёт файлы на диск
и никак не сигнализирует. NonTorrent работает иначе: поллер движка каждые
2 секунды сверяет файлы раздачи на диске с манифестом торрента. Как только
размер файла на диске совпал с ожидаемым (куски дописались), файл мгновенно
уходит в очередь сканера. Итог: к моменту, когда раздача завершится, бо́льшая
часть файлов уже проверена, а вердикты видны в журнале. После финала раздачи
весь её каталог сканируется ещё раз, полностью.

Ключевые поля состояния, за которыми следит поллер (`src-tauri/src/engine.rs`):

- `scanned_paths` — какие файлы уже ушли в сканер (не проверяем дважды);
- `completed_scanned` — какие раздачи уже прошли полный финальный скан;
- `scan_states` — агрегированный вердикт по раздаче (худший из вердиктов файлов).

## Ступени конвейера

Файл проходит ступени по нарастающей: чем подозрительнее файл, тем больше
движков к нему подключается. Это бережёт лимиты внешних API и время.

### 1. SHA-256

Файл хэшируется потоково (64 КБ буфер, файл не читается целиком в память).
Хэш — первичный ключ: по нему кэшируются вердикты VirusTotal, по нему
именуются файлы в карантине. Одинаковые файлы из разных раздач не проверяются
дважды.

### 2. Эвристика

Локальные проверки без внешних зависимостей:

| Проверка | Что ловит |
|---|---|
| EICAR-сигнатура | тестовый образец (и заодно валидирует сам конвейер) |
| PE/MZ-заголовок в «не-исполняемом» файле | полиго́ты: «картинка.jpg», начинающаяся с `MZ` |
| Рискованные расширения | exe, msi, scr, bat, cmd, ps1, vbs, jar, lnk, dll и др. |
| Двойное расширение | `photo.jpg.exe` — маскировка под безопасный тип |
| Энтропия > 7.9 на исполняемых форматах | упаковщики и шифровальщики (UPX и пр.) |

Вердикт «подозрительно» — не приговор, но повод подключить тяжёлые движки.

### 3. clamd (ClamAV)

Если в настройках указан адрес демона (по умолчанию `127.0.0.1:3310`), файл
уходит на полную сигнатурную проверку по протоколу `INSTREAM`: поток кусками
по 8 КБ, clamd отвечает `stream: <сигнатура> FOUND` либо `OK`. Подключается к
подозрительным файлам и всем файлам до 10 МБ.

```
cargo install — не нужно: достаточно запустить clamav-daemon
sudo apt install clamav-daemon
```

### 4. VirusTotal (v3 API)

По SHA-256 запрашивается отчёт `GET /files/{sha256}`. Файл **не загружается**
на серверы — уходит только отпечаток. Ключ берётся в таком порядке
(`src-tauri/src/vt.rs`):

1. свой ключ из настроек приложения;
2. переменная окружения `NT_VT_API_TOKEN`;
3. встроенный ключ приложения — он хранится **обфусцированным** (XOR с
   циклическим ключом, разбит на три константы) и восстанавливается только
   в памяти на момент запроса. Это защита от тривиального `strings`-дампа
   бинарника, а не от полного реверса — для приватности лучше свой ключ
   или переменная окружения. Встроенный источник отключается в настройках.

Бесплатный тариф: 4 запроса/мин, 500/день. Движок:

- выдерживает рейт-лимит (минимум 16 секунд между запросами);
- кэширует вердикты в памяти по хэшу;
- ответ 404 («отпечаток неизвестен») трактуется как «чисто».

Если `malicious > 0` или `suspicious > 0` — вердикт «угроза», в отчёт пишется
сколько движков среагировало из скольких.

### 5. Карантин

Файл с вердиктом «угроза» (если включён авто-карантин) изолируется:
`<appdata>/quarantine/<имя>.<хэш>.quarantined`, рядом пишется
`*.meta.json` с исходным путём, хэшем и временем. Карантин можно вызвать и
вручную из журнала проверок. Файл переименовывается — даже случайный двойной
клик по нему ничего не запустит.

## Агрегация вердиктов

Приоритет: `malicious > suspicious > clean > pending`. Вердикт раздачи —
худший из вердиктов её файлов. Прогресс сканирования (`Проверка 12/18`) виден
прямо в строке загрузки, сработавшие движки перечислены в каждой записи
журнала.

## Ограничения (честно)

- Эвристика ловит маскировку, но не содержимое: упакованный под сигнатуры
  вредонос без clamd/VT может пройти как «подозрительный», а не «угроза».
- VirusTotal — репутационный источник: новый частный malware может не иметь
  отчёта. 404 = «неизвестно», а не «безопасно».
- Кэш VT в памяти: после перезапуска приложения отпечатки запрашиваются заново
  (в рамках лимитов). Кэш на диск — в роадмапе.
- YARA-правила и оффлайн-базы ClamAV — следующий шаг (см. roadmap в README).

NonTorrent не заменяет полноценный антивирус с резидентной защитой — он
перехватывает угрозы в момент, когда они ещё лежат в папке загрузок, и даёт
честную картину того, что именно ты скачал.
